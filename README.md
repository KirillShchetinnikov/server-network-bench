# Проверки сервера и сети

Один запуск выполняет восемь проверок по очереди: IP region, Censorcheck (геоблок и DPI), тест до российских iPerf3 серверов, YABS, IP Quality Check, bench.sh и однопоточный тест CPU в sysbench.

## Запуск

На Linux сервере нужны Bash, curl и доступ в интернет. Для последней проверки установите `sysbench`; без него она будет помечена `SKIPPED`. Остальные утилиты, нужные отдельным проверкам, могут устанавливаться или запрашиваться самими исходными скриптами.

```bash
git clone https://github.com/KirillShchetinnikov/server-network-bench.git
cd server-network-bench
bash run.sh
```

По умолчанию скрипт запускается в фоне и продолжает работать после закрытия терминала. Он сразу покажет путь к файлу `live-output.log` для наблюдения за ходом проверки и пути к текстовому и Markdown отчётам. В той же папке сохраняются PID процесса (`pid`) и копия запущенного скрипта (`runner.sh`).

Чтобы выполнять проверки в текущем терминале и видеть весь вывод сразу:

```bash
bash run.sh --foreground
```

Выбор отдельных проверок:

```bash
bash run.sh --list
bash run.sh --only ip-region --only censorcheck-geoblock
bash run.sh --foreground --only ip-region
bash run.sh --only ipquality  # прежнее имя для --only ip-check
```

Вывод каждой проверки сохраняется в `reports/ГГГГ-ММ-ДД_ЧЧ-ММ-СС_UTC/<имя>.log` относительно текущего каталога. В той же папке создаются `server-report-ГГГГ-ММ-ДД_ЧЧ-ММ-СС_UTC.txt` и одноимённый файл `.md` с таблицами и оформленными логами. В обоих отчётах сначала идут очищенные логи, затем общая сводка: имя сервера, ОС, ядро, публичные и локальные IP, uptime, CPU, память, диск, статус и длительность каждой проверки. Публичные адреса запрашиваются через [ipify](https://www.ipify.org/); если сервис недоступен, выводится `н/д`. Общее время также включает сбор данных сервера. Сводка показывается в терминале. `summary.tsv` содержит статус и длительность в секундах для автоматической обработки. Папку можно переопределить переменной `REPORT_DIR`. Другие проверки продолжаются, если одна завершилась ошибкой. При любой ошибке загрузки или выполнения общий код выхода равен 1. `SKIPPED` означает отсутствие `sysbench` и не считается ошибкой. Статус «завершено» показывает только код выхода команды, а не доступность проверяемых сервисов.

Каждая сторонняя проверка запускается в своём временном каталоге рядом с текущим каталогом. После завершения скрипта он удаляется вместе с загруженными программами и промежуточными файлами, например `speedtest-cli` и `geekbench_claim.url`. Каталог отчётов сохраняется. Если текущий каталог недоступен для записи, временный каталог создаётся в системном `/tmp`; тогда тест диска измеряет файловую систему `/tmp`.

В начале текстового и Markdown отчётов указана ссылка на этот проект. Под названием каждой проверки приведена ссылка на её исходный код в GitHub; названия в Markdown сводке тоже открывают соответствующие репозитории.

Запуск напрямую через GitHub Pages на своём домене:

```bash
bash <(curl -fsSL https://bench.kipik1.ru/run.sh)
```

Эта команда также запускает проверки в фоне. Для запуска в терминале добавьте `--foreground` в её конец. При фоновом запуске через ссылку скрипт сохраняет опубликованную копию в папку отчёта перед отсоединением.

Страница с описанием доступна по адресу <https://bench.kipik1.ru/>.

По умолчанию YABS запускается с `-4`: это выбор **Geekbench 4**, как в исходной команде. Если нужна проверка IPv4 на более новой версии Geekbench, параметр следует изменить.

Для IP Quality используется прямой скрипт `ip.check.place`: адрес `check.place` открывает интерактивное меню. Флаг `-y` разрешает скрипту устанавливать недостающие зависимости без запроса ввода. Прежние проверки `ip-check` и `ipquality` запускали один и тот же скрипт дважды; теперь он запускается один раз, а `--only ipquality` служит синонимом `--only ip-check`.

Цветовые и другие управляющие коды терминала удаляются из вывода сторонних скриптов перед показом и сохранением в `live-output.log`, отдельных логах и общем отчёте. Поэтому команды очистки экрана в IP Quality и bench.sh не стирают историю вывода.
Повторные кадры индикаторов прогресса не склеиваются в длинные строки; у IP Quality рекламная заставка перед результатами опускается.

Скрипт загружает и выполняет актуальные версии сторонних программ во время запуска. Некоторые проверки активно нагружают CPU, диск и сеть, могут расходовать трафик и создавать временные файлы. Запускайте их на сервере, который вы контролируете, после просмотра исходников по ссылкам ниже.

## Проверка шифрованного DNS

Отдельный скрипт [check-encrypted-dns.sh](check-encrypted-dns.sh) проверяет 41 DNS-сервис: отправляет запрос `example.com A` через DoH (HTTPS/443) и DoT (TLS/853), проверяет TLS-сертификат и корректность DNS-ответа. Он запускается отдельно от `run.sh`, в текущем терминале. Нужны Bash 4+, `curl`, `python3` и стандартные Linux-утилиты.

После клонирования репозитория:

```bash
cd server-network-bench
bash check-encrypted-dns.sh
```

Или без клонирования:

```bash
bash <(curl -fsSL https://bench.kipik1.ru/check-encrypted-dns.sh)
```

Настройка домена и таймаута (по умолчанию `example.com` и 5 секунд):

```bash
TEST_DOMAIN=example.org TIMEOUT=3 bash check-encrypted-dns.sh
```

Чтобы проверить только свои адреса, передайте записи в кавычках. Аргументы заменяют встроенный список:

```bash
# Один hostname: DoT и DoH по стандартному пути /dns-query.
bash check-encrypted-dns.sh 'Google|dns.google'

# Только DoH; только DoT; разные адреса для двух протоколов.
bash check-encrypted-dns.sh \
  'DoH only|https://dns.google/dns-query' \
  'DoT only|dns.google|' \
  'Cloudflare|one.one.one.one|https://cloudflare-dns.com/dns-query'
```

`OK` означает успешный ответ с `rcode=0` и хотя бы одной записью. `SKIP` — адрес протокола не указан. `BLOCKED` — проверка завершилась ошибкой; это само по себе не доказывает намеренную блокировку.

В подробных результатах `query` показывает время обмена запросом и ответом в миллисекундах без установки соединения, а `total` — общее время с подключением и TLS. Для DoH `query` отсчитывается от готовности соединения к передаче HTTP-запроса до получения полного ответа; для DoT — непосредственно перед отправкой DNS-запроса до получения полного ответа. Это один замер, а не среднее значение. В сводной таблице и итоговом списке доступных DNS также указано время `query` отдельно для каждого протокола.

Скрипт дополнительно проверяет перехват незашифрованного DNS по UDP/53 и TCP/53 запросами к адресам TEST-NET. `INTERCEPTED` означает, что получен корректный DNS-ответ от адреса, который не должен обслуживать публичный DNS: это признак перенаправления запросов. `NO_REPLY` — ответа нет, `INCONCLUSIVE` — результат неопределённый. Отсутствие ответа не исключает выборочный перехват. В конце скрипт выводит адреса только тех DoH/DoT-сервисов, которые успешно прошли проверку.
