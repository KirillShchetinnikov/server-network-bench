# Проверки сервера и сети

Один запуск выполняет девять проверок по очереди: IP region, Censorcheck (геоблок и DPI), тест до российских iPerf3 серверов, YABS, IP.Check.Place, bench.sh, IPQuality и однопоточный тест CPU в sysbench.

## Запуск

На Linux сервере нужны Bash, curl и доступ в интернет. Для последней проверки установите `sysbench`; без него она будет помечена `SKIPPED`. Остальные утилиты, нужные отдельным проверкам, могут устанавливаться или запрашиваться самими исходными скриптами.

```bash
git clone https://github.com/KirillShchetinnikov/server-network-bench.git
cd server-network-bench
bash run.sh
```

По умолчанию скрипт запускается в фоне и продолжает работать после закрытия терминала. Он сразу покажет путь к файлу `live-output.log` для наблюдения за ходом проверки и путь к итоговому отчёту. В той же папке сохраняются PID процесса (`pid`) и копия запущенного скрипта (`runner.sh`).

Чтобы выполнять проверки в текущем терминале и видеть весь вывод сразу:

```bash
bash run.sh --foreground
```

Выбор отдельных проверок:

```bash
bash run.sh --list
bash run.sh --only ip-region --only censorcheck-geoblock
bash run.sh --foreground --only ip-region
```

Вывод каждой проверки сохраняется в `reports/ГГГГ-ММ-ДД_ЧЧ-ММ-СС_UTC/<имя>.log` относительно текущего каталога. В этой же папке создаётся единый текстовый файл `server-report-ГГГГ-ММ-ДД_ЧЧ-ММ-СС_UTC.txt`: полный вывод всех проверок и краткий итог в конце. Сводка также показывается в терминале. `summary.tsv` остаётся для автоматической обработки. Папку можно переопределить переменной `REPORT_DIR`. Другие проверки продолжаются, если одна завершилась ошибкой. При любой ошибке загрузки или выполнения общий код выхода равен 1. `SKIPPED` означает отсутствие `sysbench` и не считается ошибкой. Статус «завершено» показывает только код выхода команды, а не доступность проверяемых сервисов.

Каждая сторонняя проверка запускается в своём временном каталоге рядом с текущим каталогом. После завершения скрипта он удаляется вместе с загруженными программами и промежуточными файлами, например `speedtest-cli` и `geekbench_claim.url`. Каталог отчётов сохраняется. Если текущий каталог недоступен для записи, временный каталог создаётся в системном `/tmp`; тогда тест диска измеряет файловую систему `/tmp`.

Запуск напрямую через GitHub Pages на своём домене:

```bash
bash <(curl -fsSL https://bench.kipik1.ru/run.sh)
```

Эта команда также запускает проверки в фоне. Для запуска в терминале добавьте `--foreground` в её конец. При фоновом запуске через ссылку скрипт сохраняет опубликованную копию в папку отчёта перед отсоединением.

Страница с описанием доступна по адресу <https://bench.kipik1.ru/>.

По умолчанию YABS запускается с `-4`: это выбор **Geekbench 4**, как в исходной команде. Если нужна проверка IPv4 на более новой версии Geekbench, параметр следует изменить.

Для IP Quality используется прямой скрипт `ip.check.place`: адрес `check.place` открывает интерактивное меню. Флаг `-y` разрешает скрипту устанавливать недостающие зависимости без запроса ввода.

Цветовые и другие управляющие коды терминала удаляются из вывода сторонних скриптов перед показом и сохранением в `live-output.log`, отдельных логах и общем отчёте. Поэтому команды очистки экрана в IP Quality и bench.sh не стирают историю вывода.

Скрипт загружает и выполняет актуальные версии сторонних программ во время запуска. Некоторые проверки активно нагружают CPU, диск и сеть, могут расходовать трафик и создавать временные файлы. Запускайте их на сервере, который вы контролируете, после просмотра исходников по ссылкам ниже.
